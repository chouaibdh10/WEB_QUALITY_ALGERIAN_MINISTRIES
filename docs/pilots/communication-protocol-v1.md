# Communication ministry pilot protocol v1

Frozen before new collection on 19 October 2026. Target selected for being a public ministry site with news, contact and appointment paths. This is a pilot, not a nationally calibrated index score or ranking. The existing 57-row, 100-point rubric and category budgets are unchanged.

## Collection

Use the existing passive collector: exact root homepage plus up to five observed same-origin pages selected by its deterministic discovery rule. Three Lighthouse runs per page per device profile, simulated throttling and default Lighthouse device profiles, four concurrent requests maximum, 1.5-second document pacing. Record Node, Chrome, axe, Lighthouse versions and actual timestamps. Physical network and geographic location are unverified; do not infer either from OS timezone. Respect robots policy and stop on 429/503. No login, personal data, form submissions, guessed sensitive paths or exploit testing. Inspect available service/contact, news, organization and language paths manually after automated collection, documenting omissions. Do not replace failed measurements with zero or relax TLS validation.

## Award rules

Use only full / half / zero of each row budget, except N/M for insufficient evidence. A verified failure in any measured sample prevents full credit for that row. Multiple defects are not double-deducted within a row. No extra points for Lighthouse aggregate scores.

Performance rows use the worst median across sampled page/device pairs with three successful runs per pair. LCP: full <=2500ms, half <=4000ms, zero above. CLS: full <=0.1, half <=0.25, zero above. Responsiveness: lab TBT proxy explicitly, full <=200ms, half <=600ms, zero above; this does not establish field INP. Server/content: full FCP <=1800ms AND document response <=800ms; half FCP <=3000ms AND response <=1800ms; zero otherwise. Resources: full <=2MB transferred AND <=80 requests, half <=4MB AND <=150 requests, zero otherwise. Consistency: full max/min LCP <=1.5 across repetitions of each page/profile; half <=2; zero above. A missing/constrained sample prevents a positive pass and remains N/M unless an independently measured failure establishes zero. These are project pilot thresholds, not an official standard.

Security: HTTPS full requires observed HTTP upgrade with no downgrade; certificate full requires normal trust-verified hostname/date evidence. HSTS full >=31536000 max-age with includeSubDomains, half valid positive shorter or narrower policy, zero missing/disabled/invalid. CSP full requires enforced meaningful restrictive script/object/base policy without unrestricted sources or unsafe script allowances, half an enforced limited policy, zero missing/report-only/ineffective. Other headers full when nosniff, anti-framing (CSP frame-ancestors or DENY/SAMEORIGIN), and meaningful referrer policy are observed; half when some are; zero none. Cookies: full all observed cookies Secure, HttpOnly where not demonstrably required by client JS, SameSite Lax/Strict; half a subset; zero no protection; no cookies observed means N/M. Mixed content full only with an unconstrained loaded sample free of HTTP resources, zero confirmed mixed resources, otherwise N/M. Version exposure zero confirmed unnecessary server/runtime version strings, half product-only, full none within reviewed headers/metadata. Complete TLS protocol/cipher enumeration and sensitive-configuration exposure stay N/M unless adequate non-invasive evidence exists. Tracking requires a reviewed request inventory; absence of detected trackers is sample-bounded, not a privacy certification.

Accessibility: manually corroborated axe A/AA violations determine relevant rows: zero for verified severe/systemic failures, half localized defects, full only after relevant manual sample checks without defects. The general WCAG row cannot receive full from axe alone. Keyboard and focus require an actual tab/menu/escape path and recorded visible focus. Form review is inspection only; submission/error handling remains N/M when it cannot be verified safely. Process accessibility is N/M without the complete process. Automated contrast/alt/name failures must be corroborated in captured evidence; no finding is not proof of conformity.

Mobile: full after successful tested viewport/task, half localized friction, zero verified blocking failure. Navigation and interface consistency need comparison of measured pages. Journey task: locate the appointment request, read instructions and reach a usable unsubmitted form; full the declared pre-submission task succeeds, half a reachable path with missing guidance/friction, zero blocked path. No claim of completed booking or back-end success. Submission recovery is N/M without evidence. Reflow inspected at 390px and 320px; orientation landscape, controls and content inspected manually. Low-count/special-case tiny inline targets are not automatic WCAG failures.

Content: full requires the relevant readable, coherent ministry/service information in the observed sample; half material omissions; zero an actually checked required path missing/unusable. Identity requires independent government link verification; a gov.dz suffix alone is insufficient. Service function concerns only non-destructive link and pre-submission form availability. Multilingual full useful equivalent sampled pages in declared languages, half materially incomplete equivalents, zero an actually offered switch fails. Do not penalize a language never offered. Dates are publication dates, not proof all content is current.

Technical: links are a bounded set of observed internal links, not exhaustive crawling. Full/half/zero for no failures/localized failures/critical or systematic failures in the tested set. Resource errors distinguish policy blocks from intrinsic failures. Titles/descriptions, crawl configuration and canonical redirects need actual values. Search needs an actual benign keyword search and relevant results; detection alone is N/M. Obsolete technology needs verified public version and primary vendor support reference; no version is N/M. Cross-page consistency requires multiple rendered pages.

## Reporting

Review every row with evidence reference and concise rationale. Unknowns remain N/M and keep their full point budgets visible. Publish confirmed points / assessed possible points plus assessed possible points /100 as coverage. Never label this an overall final score or rank, never silently scale a partial denominator to 100. Also show the arithmetic possible final range [confirmed points, confirmed points + unmeasured budgets], explicitly a bound rather than a prediction. Reliability remains N/M until the original 28-day multi-network protocol is satisfied. Independent reviewer approval is pending; do not claim it occurred. Keep raw evidence private; publish only reviewed aggregate metrics, harmless header values, URL sources, reasons and hashes.

## Collection adaptation v1.1, recorded before successful browser observations

The recursive CDP attachment collector stalled before producing browser evidence. Its two incomplete attempts are retained privately and excluded from scoring. An abandoned earlier batch launcher was stopped to avoid competing performance work. The repeatable `scripts/pilot-communication.mjs` collector uses the existing trusted HTTP/robots/address guard and direct page-level Puppeteer interception instead, with the same 4-request cap and 1.5-second pacing. Service workers are bypassed, external document navigation and non-GET/HEAD requests blocked. Child workers are not recursively intercepted; this limitation precludes full network-absence certification. Lighthouse uses explicit guarded pages and separate browser contexts. Discovery chooses actually observed service, contact, news, organization and offered language links by fixed role patterns rather than the generic collector's random slot. Missing roles are declared, not invented. Manual observations are separately timestamped and cannot replace unavailable performance results. This adaptation does not alter point thresholds.

## Collection adaptation v1.2

Local filtering returned a synthetic `Web Page Blocked` document (HTTP 500, no ministry DOM) for some ordinary browser loads. All such documents and their axe/performance findings are excluded; they are not attributed to the ministry. Explicit-page Lighthouse also stalled. Repeated timing collection therefore uses the standard Lighthouse CLI with a fresh Chrome process for each run and its declared mobile/desktop emulation, after robots and URL scope review. The timing mode uses normal browser concurrency, not the earlier four-request cap, and runs sequentially. It does not operate forms, authenticate, or submit citizen data. Normal browser subresources are not exhaustively intercepted in this mode; resource/privacy absence claims remain unmeasured. Existing test/failed trial reports are excluded from scored medians. Observation mode uses a normal Chrome UA, GET/HEAD interception and records any resulting limitations. This is an operator-network lab experiment, not a geographically verified benchmark. Thresholds are unchanged.
